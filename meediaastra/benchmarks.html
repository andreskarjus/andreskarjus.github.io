Plain-Language Summary

This report tests large language models as article annotators on three Astra benchmark sets. Each model received one text at a time, together with the same coding scheme used for human annotation, and its structured answer was compared with a consensus human answer and with the set of individual human ratings. The model roster covers closed/API models such as GPT, Gemini, Claude, Qwen, and some open-weight models such as Gemma, DeepSeek, Mistral, and Cohere Command A.

There is no single overall winner. Performance depends strongly on the task and metric, and many bolded winners are only marginally ahead of the next model. On the core article benchmark, exact consensus scores look fairly high for some models, with gemini-3.1-pro-preview-minimal highest on mean exact consensus (0.7980) and command-a highest on the mixed primary metrics (0.4665). The top-two gap on this metric is only 0.0097, so the ranking should be read as a near-tie rather than a clear separation. However, this set should be treated as exploratory rather than decisive: the human inter-rater materials show weak agreement on important parts of the task, including sentiment and especially topic sets, and many easy NA / no-label fields inflate averages.

The hate benchmark is stricter than it may look because the expected answer is a set of labels. Exact set match is low even for the best models: gemini-3.5-flash-medium reaches 0.5118 mean exact consensus. Multi-label detection is more informative here; qwen-3.7-max-none has the best mean primary score (0.7474), close to the human-vs-consensus micro-F1 average (0.7409). The top-two gap on this metric is only 0.0110, so the ranking should be read as a near-tie rather than a clear separation. This suggests models can often detect relevant labels, but exact agreement on the full label set remains difficult. The second hate set's strength suffixes were collapsed to base-label presence for this benchmark, so these results compare label detection rather than intensity or severity scoring.

The politics benchmark has two different problems: first, deciding whether a dimension is applicable at all (NA vs numeric), and second, placing applicable cases on a 1-7 scale. Models are reasonably good at the first problem: claude-sonnet-4.6-none has the best mean presence accuracy (0.8693), compared with human-vs-consensus presence accuracy around 0.9360. The top-two gap on this metric is only 0.0078, so the ranking should be read as a near-tie rather than a clear separation. They are much weaker on exact numeric placement: the lowest model mean absolute error is gpt-5.4-none at 1.6045 scale points, while humans average about 0.5164. The highest mean exact consensus score on politics is deepseek-v4-flash (0.7744). The top-two gap on this metric is only 0.0026, so the ranking should be read as a near-tie rather than a clear separation.

For practical use, read this as a task-by-task comparison rather than a global leaderboard. A bold score marks the best value in that table, but not always a practically meaningful lead. The most useful tables are the feature-level tables and the politics numeric-distance columns, because they show where a model is actually matching human annotation behavior and where high averages are mostly driven by easier absence/NA decisions.

How To Read The Metrics

The scoring follows the same conventions as the inter-rater summaries where applicable: list outputs are treated as unordered sets, explicit NA and empty-list/no-label outputs are real labels rather than missing data, and politics 1-7 scores are treated as ordinal values with NA handled separately.

How To Catch These Before A Long Run

  • Run a schema preflight: one item per benchmark task and model before launching a full matrix.
  • Check OpenRouter catalog parameters for each model: structured_outputs, response_format, reasoning, and temperature are not uniformly supported.
  • Reject unsupported JSON Schema features before sending requests. Observed failures included OpenAI rejecting uniqueItems on arrays and $ref schemas carrying extra keywords such as descriptions, and Cohere rejecting array constraints such as maxItems.
  • Keep Pydantic validation after the provider response. Qwen produced out-of-enum labels in a few runs, and Gemma/Cohere occasionally returned invalid or truncated JSON.
  • Classify retry behavior by error type. DNS failures, refused connections, server disconnects, and incomplete chunked responses are retryable with backoff. Schema rejections, moderation blocks, and repeated enum validation failures should be quarantined until the schema or prompt is changed.
  • Merge by benchmark, model_id, and item_id, keeping valid records only, so repairs replace failed attempts without changing the benchmark item denominator.
